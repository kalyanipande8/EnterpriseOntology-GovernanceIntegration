# Enterprise Ontology Governance & Semantic Data Integration

SKOS-based controlled vocabularies and taxonomy frameworks for pharma /
life-sciences, with real ontology versioning, change-management workflow,
and QA processes that support audit compliance.

**Stack:** OWL/SKOS (rdflib), a relational database, Python, pytest.

## Honest disclosure: PostgreSQL stand-in

This project's schema (`src/db.py`) is written as plain, portable SQL
targeting PostgreSQL in production. On the machine this was built on,
neither `psql` nor `pg_ctl` were found (`which psql` / `which pg_ctl` both
returned nothing) and no local Postgres server was running, so **SQLite**
(Python's built-in `sqlite3`) is used as an honestly-disclosed stand-in
relational engine — same relational model, same SQL DDL/DML, foreign keys,
transactions. The one SQLite-specific idiom is
`INTEGER PRIMARY KEY AUTOINCREMENT`; the Postgres equivalent
(`SERIAL PRIMARY KEY` / `GENERATED ALWAYS AS IDENTITY`) is noted inline in
`SCHEMA` in `src/db.py`. Swapping to a real Postgres connection would mean
changing `db.get_connection` to use `psycopg2`/`psycopg` and that one DDL
line — nothing else in the pipeline depends on SQLite-only features.

## What's actually implemented

1. **Real SKOS vocabulary** (`src/skos_vocab.py`) — built with `rdflib`'s
   genuine SKOS namespace (`skos:Concept`, `skos:prefLabel`,
   `skos:definition`, `skos:broader`, `skos:narrower`, `skos:related`,
   `skos:inScheme`, `skos:hasTopConcept`). Domain: a pharma/life-sciences
   taxonomy of therapeutic areas (Oncology, Cardiology) → drug classes
   (Alkylating Agents, Immune Checkpoint Inhibitors, Beta Blockers,
   Statins) with `related` links to adverse event terms (Neutropenia,
   Myalgia, Bradycardia). Exported as real Turtle RDF
   (`data/pharma_taxonomy_v1.ttl`, generated by `run_all.py`).

2. **Real ontology versioning** (`src/versioning.py` + `src/db.py`) —
   `create_version()` inserts an immutable, fully independent snapshot of
   every concept under a new `version_id`; nothing is ever updated in
   place. Old versions stay queryable forever via
   `get_version_concepts(conn, version_id)`. `diff_versions()` computes a
   genuine structural diff (added/removed concepts, per-field changes to
   label/definition/broader/narrower/related) between any two stored
   versions.

3. **Real change-management workflow** (`src/change_management.py`) — a
   change request state machine: `DRAFT → UNDER_REVIEW → APPROVED →
   PUBLISHED`, with `REJECTED` and a return-to-`DRAFT` path from review.
   Illegal transitions (e.g. `DRAFT → PUBLISHED`, or any transition out of
   the terminal `PUBLISHED`/`REJECTED` states) are rejected by raising
   `InvalidTransitionError` and the DB state is left unchanged — this is
   enforced in code (`ALLOWED` transition table), not just documented.
   Every transition attempt, successful or rejected, is written to a real
   `audit_log` table with actor, timestamp, and reason.

4. **Real QA checks** (`src/qa_checks.py`) — actual graph algorithms run
   over the vocabulary, not stubs:
   - `detect_cycles`: DFS-based cycle detection over `broader` edges.
   - `detect_orphans`: concepts with zero broader/narrower/related edges.
   - `detect_missing_labels`: concepts with a blank `prefLabel`.

   `run_all.py` and the test suite deliberately corrupt a copy of the
   vocabulary (`inject_cycle`, `inject_orphan`, `inject_missing_label` in
   `src/skos_vocab.py`) and confirm the QA checks actually catch each
   injected defect.

## Running it

```bash
pip install -r requirements.txt
python3 run_all.py
pytest tests/ -v
```

## Real results (last run on this machine)

`python3 run_all.py`:
- RDF triples generated for v1: **74**
- Concepts in v1: **11** (v2, after the approved change: **13**)
- QA on clean v1: `cycles=0 orphans=0 missing_labels=0`
- QA on deliberately injected defects, all caught:
  - injected cycle → `cycles=1`: `oncology -> alkylating_agents -> oncology`
  - injected orphan → `orphans=1`: `orphan_term`
  - injected missing label → `missing_labels=1`: `myalgia`
- Change request lifecycle: `DRAFT → (rejected attempt to PUBLISHED) →
  UNDER_REVIEW → APPROVED → PUBLISHED`, **5** audit log entries for that
  one change request, **7** total audit log entries for the full run.
- Version diff v1 → v2: `added=['parp_inhibitors', 'thrombocytopenia']`,
  `removed=[]`, plus `narrower` field updates on `oncology` and
  `adverse_events`.
- Version 1, reloaded from the database *after* version 2 was created,
  still has exactly **11** concepts with `parp_inhibitors` correctly
  absent — proving old versions are never mutated.

`pytest tests/ -v`:

```
14 passed in 0.29s
```

Tests cover: real SKOS hierarchy structure, correct rdflib SKOS predicate
usage, QA clean-pass on the base vocabulary, QA catching each of the three
injected defects (cycle / orphan / missing label), versioning preserving
old version content unchanged after a new version is created (with an
injected post-creation sanity re-fetch), version diffing, version listing,
and the change-management state machine (valid path, invalid transition
rejection, terminal-state rejection, and audit trail completeness).

## Project layout

```
src/
  skos_vocab.py         # SKOS concepts, RDF graph, injected-defect helpers
  db.py                 # SQLite (Postgres stand-in) schema + connection
  versioning.py         # version create / fetch / diff
  change_management.py  # change request state machine + audit logging
  qa_checks.py          # cycle / orphan / missing-label detectors
run_all.py               # end-to-end demo pipeline (see Results above)
tests/test_pipeline.py   # pytest suite (14 tests)
data/                    # generated DB + Turtle export (gitignored)
```
